# 整理学习笔记

目标是让用户自己的内容更容易阅读、复习和继续修改。

## 工作步骤

1. 如果用户给的是文件路径，先用现有读取工具取得原文；如果内容已经在对话中，不重复索取。
2. 识别笔记主题、主要观点、例子与未解决的问题。只有缺失信息会改变原意时才追问。
3. 删除口头重复，调整顺序，按内容需要组织标题和段落。保留必要的代码、例子和推导。
4. 检查成稿是否保留原意，尤其是疑问、条件和不确定性。
5. 用户只要求整理时，在对话中交付 Markdown。只有明确要求保存、创建或修改文件时才使用写入工具，修改前读取当前 revision。

## 内容与风格

- 使用简洁、自然的中文，不添加宣传性语言、空泛引言或固定的总结段。
- 只保留内容需要的标题层级，不强行填充背景、原理、优缺点等固定栏目。
- 不把用户的推测改成事实，不把待确认方案写成已确认决定。
- 不凭空补充论据、来源、实验结果或代码运行结果。
- 如果用户要求补充知识，将补充与原始观点明确区分；没有核实的内容标为待确认。
- 原文存在疑似错误时，明确指出疑点，避免悄悄改写成另一个意思。
- 输出整理后的正文即可；存在重要歧义或补充时，再用短段落说明。

## 示例

原始内容：

> agent 每次调用模型都要把之前的东西带进去吧，工具返回也会越来越多。
> 我感觉可以把早期的内容总结一下，但不确定会不会把用户的要求给丢了。
> 完整记录还是留着。

整理结果：

```markdown
# Agent 的上下文管理

Agent 在后续模型请求中需要携带相关历史。随着工具结果增加，上下文也会增长。

一个待验证的方案是：将早期内容压缩为摘要，同时保留完整的原始记录。

## 待确认的问题

- 压缩是否会丢失用户要求？
- 如何验证摘要保留了继续执行所需的信息？
```

这个例子保留了“方案尚未验证”的状态。实际整理时按原文组织，不强行套用示例结构。
